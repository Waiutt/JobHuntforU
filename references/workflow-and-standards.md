# 第一部分：工作流（8 步）

```
① 定方向 → ② 扫岗 → ③ 查重 → ④ 找官网入口&登录
                                  ↓
⑧ 记台账 ← ⑦ 抓回执 ← ⑥ 你提交 ← ⑤ 做简历+填表
```

**红线：第 ⑧ 步没拿到站内回执，不许写「已投」。**

## 每轮开场固定动作

```
1. 读台账       → 现在多少行、状态分布
2. 问用户取向    → 今天投哪家 / 继续扫哪个赛道
```

## 扫邮箱：**周期性**，不必逐轮

**用户 2026-11-01 明确：「周期性扫邮箱就行，不需要每天扫」。**

| 项 | 口径 |
|---|---|
| 频率 | **不逐轮扫**；隔几日、或用户开口要「看看有没有新消息」时扫 |
| 扫就必须提 | 凡带**截止时间**的（笔试 / 测评 / 面试 / AI 面 / 到期提醒）**当场列出来**，不能扫了不说 |
| 依据 | 原则 13.4 —— 邮件标题常是「ai面试到期提醒」，一不留神就滑过去 |
| 提醒排序 | 已过期 > 24h 内到期 > 3 日内到期 > 待企业发时间 |

## 各步要点速览

| 步骤 | 要点 | 产出 |
|---|---|---|
| ① 定方向 | 岗位优先级 + 城市优先级 + 渠道 | 四赛道目标清单 |
| ② 扫岗 | web_search → 官网 → 招聘页；逐条读 JD 找硬门槛 | 候选岗位表 |
| ③ 查重 | 台账按**公司主体（含别名）**匹配 | 可投/锁定 |
| ④ 找入口 | 🔴 **先 web_search 找官网，禁止猜域名**；官网网申直链；**用户先登录**；**先看额度** | 可填写的表单 |
| ⑤ 做简历+填表 | 覆盖率 ≥85% → 上传 → 解析 → 补缺 → **核对项目区** → **点暂存** | 待提交表单 |
| ⑥ 提交 | **必须人工点**「预览并提交」 | 提交动作 |
| ⑦ 抓回执 | 北森 `personal/deliveryRecord`；飞书 `position/application` | **站内原文** |
| ⑧ 记台账 | `_append_json_row.py` + `_verify_ledger.py` | 台账 +1 行 |

# 第二部分：投递原则（16 条）

## 原则 0️⃣ 🔴 **优先搜索官网，不要猜域名**（最高优先级）

**这是整个流程的第一原则。找入口一律先 `web_search`，禁止猜域名。**

### 为什么

| 方法 | 命中率 | 结论 |
|---|---|---|
| 猜 `拼音.zhiye.com` | **36 家 0 命中** | ❌ **彻底失效，一次都别再试** |
| 猜 `app.mokahr.com/campus-recruitment/<slug>` | 26 家 3 命中 | ❌ 命中率 11%，浪费时间 |
| **`web_search` → 官网 → 「加入我们/人才招聘」→ 网申直链** | **多次全中** | ✅ **唯一可靠路径** |

### 标准动作

```
1. web_search 搜「<公司名> 2027届校园招聘 官网」或「<公司名> 招聘 加入我们」
2. 从结果里识别【官网域名】（不是第三方招聘站）
3. 打开官网 → 找「加入我们 / 人才招聘 / 校园招聘 / Careers」
4. 在官网找【网申通道直链】（可能是北森 / Moka / 问卷网 / 飞书招聘）
5. 打开直链 → 用户登录 → 看额度
```

### 已验证命中的公司（全部靠搜索，无一靠猜）

中兴新云 · MiniMax · 广和通 · 自变量机器人 · 天正电气 · 科华数据 · 聚光科技 · 时空壶 · Rokid 若琪

### 反例（猜域名浪费的时间）

- 阳光电源：猜 `sungrow.zhiye.com` 等 3 个 → 全 404 → **后来搜到官网 `cn.sungrowpower.com/about/career` → 找到 `jobs.sungrowpower.com`**
- 科华数据：猜 3 个 → 全 404 → 搜索后从官网找到
- 聚光科技：猜 2 个 → 全 404 → 搜索后从官网「加入我们」拿到 `xyz.51job.com` 直链
- 天正电气：**搜索结果直接给出 `tengen.zhiye.com/campus`**，零试错

**⇒ 一律先搜，搜不到再想别的办法。**

## 原则 1️⃣ 只走企业官网 / 官方 ATS

招聘网站（BOSS、前程无忧、智联、猎聘、牛客）**只用于扫岗，不作投递渠道**。

**为什么**：官网投递有站内回执可查；第三方渠道投递后状态不可控、无法验证。

## 原则 2️⃣ 投递过即锁定

**台账有任何该公司的记录 ⇒ 永久锁定，不再投。**

**必须按公司主体合并别名**：
| 别名组 | 说明 |
|---|---|
| 掌上先机 = 慧策 | 同一家 |
| 安克 = Anker | 同一家 |
| 荣耀 = HONOR | 同一家 |

## 原则 3️⃣ 额度优先于永久锁定

部分公司是**限额**而非永久锁定，要按额度判断：

| 公司 | 额度 | 状态 |
|---|---|---|
| 广和通 | 1 | **用满** |
| 天正电气 | 2 | **用满** |
| 宇树 | 2 | **用满** |
| MiniMax | 3 | 剩 1 |
| 优必选 | 3 | 用 1 |

**额度决定选岗策略**：额度 1 的必须选最对口的；额度 3 的可以广撒。

## 原则 4️⃣ 硬门槛不满足就不投

**看到「硬门槛」必须当场核实并说清楚，不要抱着侥幸投。**

**已判定不投的实例：**
| 岗位 | 硬门槛 | 结论 |
|---|---|---|
| 天正 J13908 海外销售 | **英语专八/俄语B2/西语4级** | ❌ CET-6 428 不满足 |
| Kimi 法律方案 | 法学背景 + 2 年律所 | ❌ |
| Kimi 金融方案 | 金融/咨询/量化实习 + 立即北京到岗 | ❌ |

**注意区分**：
- **硬门槛**（必须满足）→ 不符合就别浪费额度
- **加分项/优先考虑**（可放宽）→ 可以投

## 原则 5️⃣ 岗位方向优先级（内部排序）

```
技术支持 / 售前 / 解决方案   ← 第一优先
        ↓
平台运营 / 治理 / 产品
        ↓
销售
```

**志愿顺序必须体现这个优先级**：第 1 志愿放售前/技术支持，第 2 志愿放营销/管培。

## 原则 6️⃣ 城市优先级

```
深圳  >  上海  >  广州  >  全国可调配
```

- **校招：城市不限**（全国可调配为前提）
- **实习：只投上海**（用户 2026-10-31 明确）
- **北京：原则上排除**（用户 2026-10-31 口头「北京就算了吧」）
- 🆕 **二线城市同样投**（用户 2026-11-02 明确：「目标城市可以放在武汉等二线城市」）
  - 即 **武汉 / 合肥 / 成都 / 杭州 / 厦门 / 苏州 / 南京 / 西安 / 长沙** 等均视为**有效目标**，不再只盯深圳·上海·广州
  - 一线（深圳·上海·广州）仍**优先排序**，但**二线不再作为筛选否决项**
  - ⚠️ 配套必查项：二线城市岗位要额外确认**到岗时间要求**（尤其社招岗），避免与 2027-06 毕业时间冲突

## 原则 6️⃣-B 🔴 **校招优先于社招**（用户 2026-11-02 明确）

**同样对口时，校招 > 社招。社招岗不作为主攻方向。**

| 情形 | 处理 |
|---|---|
| 有**校招通道**（校招专属站 / 2027届批次 / 明确写应届） | ✅ **优先投** |
| **只有社招**，但 JD 写明「欢迎应届毕业生」 | ⚠️ 可投，但**降级**，且必须核对到岗时间 |
| **只有社招**，JD 无应届表述且要求年限 | ❌ 不投（同时触发原则 4） |

**投稿前必查（本次踩过）**：站内岗位标签常写明渠道，如逐际动力标「**深圳社招 - 全职**」——不看这一行就会把社招当校招投。
**教训实例**：2026-11-02 逐际动力「售后技术支持」按对口+无年限投出，事后才发现标签是「深圳社招」；该门户无校招通道，整家应降为备选。

## 原则 7️⃣ 海外业务岗要看清楚再投

**用户明确提示：「部分岗位有海外业务岗，投递看清职责」。**

**判断标准**：JD 里出现以下内容即为海外业务岗，**需先提示用户**：
- 「面向海外用户」
- Discord / Reddit / Instagram / YouTube / TikTok
- 「外文听说读写流利」
- 「全球市场推广」

**实例**：
- MiniMax AI产品市场营销 → 海外岗但无硬证书门槛 → 提示后用户决定投
- 天正 J13908 → 海外岗**且有证书硬门槛** → 明确劝阻

## 原则 8️⃣ 优先投飞书招聘站

**同样条件下，优先投飞书招聘的公司** —— 简历解析质量高，人工返工少。

## 原则 9️⃣ 提交必须人工点

**北森的「预览并提交」程序化点击（坐标 / locator / JS）全部无效 —— 已 5+ 次验证。**

**纪律：填完交用户本人点提交。**

## 原则 🔟 没拿到回执不算已投

| 平台 | 查回执路径 |
|---|---|
| **北森** | `<域名>/personal/deliveryRecord` |
| **飞书招聘** | `<域名>/position/application`（`/records`、`/application` 均 404）|
| 飞书投递成功页 | `<域名>/resume/applied` |

**要抓到「站内原文」才算数**，例如：
> 已完成的投递 (2)｜第 1 志愿 售前技术支持工程师/应届生(J13916)｜2026-10-31 19:58 投递

**拿不到站内原文时**（标签页被关、路径 404）→ **台账必须注明「依据用户口述，无站内回执」。**

## 原则 1️⃣1️⃣ 笔试 / 测评处理

### 11.1 我不代答，只负责提醒和记账

**🔴 红线：不代答笔试 / 测评。** 那是本人的考试，进去做就是替考。

**我负责三件事：**

| 职责 | 做法 |
|---|---|
| **提醒截止时间** | 每轮开始扫邮箱时，把有截止时间的列出来 |
| **记录台账** | 用户做完告诉后更新状态 |
| **保留链接与凭证** | 考试链接、通行证号、考试窗口写进 `notes` |

### 11.2 状态变化规则

```
收到笔试/测评通知  →  status 保持 Submitted，stage_detail 写「已测评/笔试·待作答」
       ↓ 用户完成
     完成           →  status 改 Assessment，stage_detail 写「已测评/笔试·待结果」
       ↓
   出结果           →  Interview / Rejected / 保持 Assessment
```

### 11.3 证据来源必须注明

| 情形 | 台账写法 |
|---|---|
| 企业邮件发了通知 | 抄邮件原文关键信息（考试窗口、链接）|
| 用户口述「都做了」 | **`（依据：用户 YYYY-MM-DD 口述「…」）`** |
| 企业还没发时间 | 保持「待笔试安排」，**不改状态** |

**实例**：吉比特 / 雷霆游戏至今是「待笔试安排」—— **企业没发时间，不是用户漏做，不能改。**

### 11.4 批量更新要留痕

**实例**：2026-10-31 用户说「测评都做了」→ 一次更新 6 条（迪普科技、上海龙旗、金蝶×2、大疆、亿滋），全部在 `notes` 注明依据。

**每条都要写变更原因 + 证据来源，不许静默改状态。**

## 原则 1️⃣2️⃣ 拒信 / 终止处理

### 12.1 两种「结束」要分开

| 状态 | 判定标准 | 含义 |
|---|---|---|
| **Rejected** | **企业明确拒绝**（邮件 / 站内显示未通过）| 被刷了 |
| **Terminated** | 流程中止（岗位关闭 / 本人放弃 / 长期无响应判定）| 不是被拒，但也没成 |

**🔴 绝不能把「没消息」标成 Rejected。**

### 12.2 必须记录拒因

`outcome_reason` 写清楚，例如：
- `三面挂`
- `在线测评未通过·2026-10-26 企业邮件`
- `岗位关闭`

有企业邮件就抄原文关键句。

### 12.3 记录不删除

**台账只增不删。** 被拒也留着 —— 用于查重、看趋势、复盘。

### 12.4 被拒后该公司锁定

按原则 2️⃣，**有记录即锁定**，不再投该公司（额度型且还有剩余额度的除外）。

### 12.5 高优先级岗位被拒要主动告知

**实例**：海康威视占 Interview 的 2/7，一面约在 10-27 结果未明 —— 这类要主动追问，不能等。

## 原则 1️⃣3️⃣ 面试跟进

### 13.1 Interview 是最有价值的状态

**Interview 条数最少（目前 7 条）** —— 这是最靠前的进展，**优先关注、优先更新**。

### 13.2 状态未知就写「未知」

**不许猜，不许留空装作有进展。**

| ❌ 错误 | ✅ 正确 |
|---|---|
| 「已通过一面」 | `一面（约 2026-10-27）· **结果未知**` |

### 13.3 面试信息要结构化

`stage_detail` 至少含：
- **轮次**（一面 / 二面 / 三面 / HR 面 / 终面）
- **时间**
- **形式**（现场 / 线上 / **AI 面**）
- **结果**（通过 / 未通过 / **未知**）

### 13.4 AI 面试也算面试

**实例**：2026-10-31 牛客网「AI Agent 产品评测实习生」AI 面试，**16:15 截止** —— 这类最容易错过，因为邮件标题是「ai面试到期提醒」，一不留神就滑过去了。

**原则：扫邮箱时，凡带「面试 / 测评 / 笔试 / 到期」字样的，都要往下看 5 行。**

### 13.5 面试结果必须由用户提供

**用户告知结果才更新台账。不替用户猜结果。**

# 第三部分：简历制作原则

## 3.1 五条铁律（最高优先级）

| # | 规则 | 校验项 |
|---|---|---|
| **1** | **比心职位统一写「策略运营」** | 不写「数据运营」 |
| **2** | **不体现「约占日常工作量 50%」** | `无50%工作量口径(用户要求)` |
| **3** | **CET-6 428 / CET-4 469** | **465 是旧错值，已废除** |
| **4** | **不暴露短板** | 禁写「不足 / 仍在练 / 尚未上手 / 尚未实操 / 薄弱 / 较弱 / 弱项 / 不熟 / 零起点」 |
| **5** | **不得出现字面字母 S / T / A / R** | 项目用 STAR 逻辑，但不写字母 |

### 铁律 4 的正确写法

| 场景 | ❌ 不要写 | ✅ 应该写 |
|---|---|---|
| 英语口语弱 | 「听说读写中读与写扎实，**口语仍在练**」 | 「具备**听说读写**基础，可顺畅阅读英文技术文档与 datasheet，并可用英文邮件往来沟通」 |
| 没做过某个技术 | 「ROS 属系统学习，**Go 尚未上手**」 | 「对 ROS 与 Ray 有系统性了解，Go 有基础语法认知——**这些正是我入职后最想马上用起来的工具**」 |
